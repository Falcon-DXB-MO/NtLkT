The problem

Core engineering tools remain licence-server, desktop installs. Collaboration happens through exported files and email.

2

Closed calculation engines

No clean programmatic access. Integration with operator data platforms and digital twins is custom, fragile and expensive.

Why now

Connected is not enough: engines must be callable

Three levels of integration. Most well engineering tools stop at the first two.

1

Read

Pull inputs from operator systems

Surveys, casing schemes, fluids and temperature data come in from the data platform, not from re-keyed spreadsheets.

2

Write

Publish results back

Load cases, APB results and separation factors go out in standard formats to digital twins and reporting.

3

Run

Compute on command

"Design this well." "Run 100 trajectories from slot to target." "Recheck APB for this shut-in." The engine executes and hands off to the next system.

The step that turns a tool into a workflow

Data sync is table stakes. Being callable on demand is what lets an AI agent or an automated design loop use the engines without a human in the middle.

AI does not raise the value of well data. It raises the cost of keeping it locked inside closed tools.

The solution

One engine set, three ways in

Every engine is exposed through the same versioned REST API. MCP is live; the SDK and CLI are on the roadmap.

MCP

Model Context Protocol

Agents discover the engines as tools and call them directly. Works with any MCP-capable model, with no glue code per model.

Best for: Autonomous agents and engineering copilots
SDK ROADMAP

Python client library

Typed functions over the API. Handles auth, retries and the common well data model, so teams script design workflows in code.

Best for: Operator data teams and digital-twin builders
CLI ROADMAP

Command-line interface

Run any engine from a shell. Batch studies and shell-based agents call it the same way an engineer would.

Best for: Batch sensitivity runs and quick automation
Same auth, tenancy, audit trail and deterministic run record behind every access path

Trust

AI orchestrates, validated physics decides

1  Orchestrate

AI agent

Interprets the request, sets up load cases, proposes candidate designs and picks the engine to call. Fast and creative, but fallible.

➤

2  Calculate

Validated engine

Thermal, tubular and trajectory engines benchmarked against incumbent results. Deterministic: same input, same answer.

➤

3  Release

Auditable result

Only designs that pass leave the loop, each with a run record the engineer of record can review and sign.

Feedback loop: every rejected candidate goes back to the agent, so the search gets smarter while the engineering stays grounded.

Precedent: algorithms   Google DeepMind AlphaEvolve, 2025

An LLM proposes code and an automated evaluator verifies it. It found a 48-multiplication method for complex-valued 4x4 matrices, one better than Strassen's 49 from 1969.

Precedent: safety-critical hardware   DeepMind and EPFL, Nature, 2022

A controller trained inside a validated plasma simulator then ran the real TCV tokamak, driving its 19 magnetic coils. Simulator first, hardware second.

The AI never invents the engineering. It runs validated engines, faster. Every action is permissioned, checked and logged, like any engineer's work.
